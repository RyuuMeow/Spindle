# Yarn Workbench 桌面設計複審

> 0.5.0 決策更新：使用者後續指定自訂指令改為設定式工具 tab，取代下方 0.4.0 的暗幕 modal 方案。顯示名稱、參數提示及點圖表空白退出的現行契約見 [UI 規範](ui-design.md)。以下保留歷史取證。

## 0.3.0 使用回饋：第二輪分析與改善方案

本節的問題基線來自使用者兩張 0.3.0 截圖、三位 Sub Agents 及主代理程式碼核對。分析階段之後，使用者已批准開始實作，並補充「正文以外物件簡單低調」。**本輪已於 0.4.0 完成實作、打包及 portable 回歸；原生操作驗證限制見實作追蹤。** 下文「根因／目前行為」均指取證時的 0.3.0，不是最新程式碼的未修缺陷清單；歷史行號也不作新版本定位依據。

最新規則與各模組實作／待驗證狀態集中於 [UI 規範](ui-design.md)，最終桌面、portable 和版本結果由 [實作追蹤](implementation-progress.md)統一記錄。本文件保留意圖、取捨和問題證據，避免再將已汰換的第一輪方案當成現行要求。

| 已汰換的第一輪規則 | 本輪替代 |
|---|---|
| 自訂指令占完整工作區／文件 tab | R01：保留原稿背景的大型暗幕 modal |
| 全文搜尋占左側持續結果欄 | R01：中央輕量 popup；查詢與結果直接相連 |
| 普通開稿優先切到其他已開 tab | R02：在目前 TabId 導航；新 tab 必須有明確意圖 |
| 新增／一般更名用命名 modal | R03：列表 inline 物件與名稱輸入 |
| 大綱的暫時開啟／pin／close 三套生命週期 | R06：單一 toggle，按模式保存偏好 |
| 小字命令跟著縮短行框、附屬物件搶主體 | R04／R08：語義間距、同行框、低調附屬資訊 |

### 最新已批准的需求

- 自訂指令應是保留編輯背景、壓暗背景的獨立大型懸浮面板，不能占用文件 tab。上一輪改成整頁工作區是意圖理解錯誤。
- 全局搜尋應是中央偏上的輕量浮層，輸入框下直接列出結果；點項目、点外部或焦點離開整個浮層就關閉，取代常駐搜尋側欄。
- 普通切換劇本只在目前 tab 導航；中鍵、tab＋及其他明確的新分頁操作才建立新 tab，不能因目標已有視圖而跳到別的 tab。
- 新增劇本、新增場景都在其列表內插入物件並立即改名，預設名称反白，不用命名對話框。
- 純文字 Monaco 保持原樣；閱讀模式需改善節奏、分隔線前後距離及條件區域對齊。
- 流程圖應能直接在節點上改台詞、角色與命令；大綱的固定／關閉與上方 toggle 重複，需簡化。

### R01：先區分三種操作容器

| 任務 | 建議容器與行為 |
|---|---|
| 劇本、閱讀、流程圖 | 保留主要工作面，文件導航不改活動 TabId |
| 自訂指令 | 大型 modal 管理面板，背景壓暗並停止接收編輯；不產生 tab，關閉恢復原稿的模式、位置和焦點 |
| 全局搜尋 | 中央偏上的輕量搜尋浮層，即搜即列結果、輕易關閉，不用大型標題／說明／確認按鈕 |
| 新增劇本／場景、一般更名 | 所屬列表內直接編輯名稱，錯誤就地顯示 |
| 大綱／結構檢查 | 可調整的停駐輔助面板，主工具列有唯一顯示開關 |

自訂指令的建議起點：寬 960–1120 CSSpx，最大寬度為視窗減 48px；高不超過 85vh，外圍保留編輯背景。面板有自己的標題／專案範圍、左側約 200px 指令清單、右側定義，標題列固定、內容獨立捲動。沿用「套用定義」與未套用草稿契約；關閉不等於偷偷套用，也不能丟棄已保留的草稿。背景使用約 35–45% 黑色遮罩，面板低對比描邊及柔和陰影，不用白邊。Esc、關閉與焦點回復需統一；全域 Ctrl+S／Undo／關閉快捷鍵不能穿透到背景文件。現有入口以 `openDocument("@commands")` 建 tab，需拆出專屬 overlay 狀態，並處理舊工作階段的 utility tab 遷移。

搜尋的建議起點：寬 600–680px，頂部約視窗高度 12–16%，窄窗保留 16–24px 邊距；輸入與結果為同一表面，結果區有最大高度及捲動。沒有查詢時可列最近項目；輸入後直接顯示命中片段、檔名／必要場景及選中行。方向鍵只移動選取，Enter／點選才導航並關閉；IME 確認候選不觸發開啟。輸入框、範圍切換與列表內的焦點移轉不算離開浮層；Esc 回焦點，點外部或 App 失焦時不搶回焦點。搜尋保留上次查詢，不保留佔位側欄。Ctrl+P 可共用容器但預設檔案範圍，工具列搜尋／Ctrl+Shift+F 預設內容範圍；tab＋使用同款容器時明示新增分頁意圖。

大型 modal 與輕量 popup 的不同責任可參照 [Windows dialogs／flyouts](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/)，但上述位置與尺寸是本產品提案，並非照抄系統規定。

### R02：Tab 是使用者建立的視圖容器

根因：[Workbench.tsx:427](../app/workspace/Workbench.tsx:427) 的 `openDocument(false)` 優先尋找全視窗第一個同文件 tab；找不到又遇到固定／utility tab 時會自動新增。共用 `past/future` 還會混入不同 tab 的導航歷史。

- 側欄單擊、搜尋結果、閱讀跳轉、同稿大綱定位：維持活動 TabId、tab 數量和順序；目標已在其他 tab 開啟也照樣在目前容器呈現。其他視圖的模式、游標、捲動都不變。
- 中鍵、Ctrl+Enter、tab＋、「在新分頁開啟」才建立新容器；直接點 tab 或 Ctrl+Tab 才切既有容器。沒有任何 tab 時建立首個容器屬初始化例外。
- 返回／前進與每份稿的閱讀位置按 TabId＋DocumentId 保存；內容和 Undo 仍按 DocumentId 共用。普通跨文件導航保留目前模式；只有明確「前往原文」才切純文字。
- 建議固定 tab 僅固定位置及防止批次關閉，不能當作默默建立新 tab 的理由。若未來要鎖定文件，需另有明確動作。
- 移除 utility 使用文件導航函式的捷徑；開關自訂指令、搜尋都不入文件導航歷史。不能為搜尋先跳到第一個文件 tab。

驗收必須包含同稿第二視圖、已固定 tab、A／B 各自返回歷史、搜尋和診斷入口；不能只驗側欄點擊。

### R03：建立物件與排序都要看得見結果

新增劇本／場景流程：插入尚未提交的暫存列 → focus 並反白唯一預設名稱 → Enter 或合法失焦確認 → 建立成功後定位；Esc 移除暫存列，不留下磁碟空檔或來源場景。中文組字中的 Enter 不提交。名稱衝突、非法字元、唯讀／I/O 失敗就地顯示並保留輸入，重試不能建立第二份。劇本的 `.yarn` 可置於輸入外；場景依既有 Yarn 名稱規則。一般 F2／更名也用相同列表內模式。

從側欄新增劇本成功後在目前 tab 開啟；從 tab＋走新增流程才開新 tab。新增場景只修改目前文件，在大綱插入列；確認前不自動寫入 `title/---/===`，確認後用來源交易插入合法骨架並定位，Undo 撤回完整新增。名稱編輯期間排序不得讓輸入列突然移位。

場景建立還需處理所有入口：圖表＋或其他「新增場景」同樣開大綱的暫存列，不能保留第二套 modal；目前大綱篩選不可隱藏正在命名的列。提交時重新核對全專案重名與最新文件版本，沿用該文件換行；成功保持原模式，圖表選取新節點。命名中換文件先取消暫存列，不把場景插進新文件。目前 `newScene` 完成後呼叫 `go()` 會切純文字，這條路徑也必須修正。

排序根因：[Workbench.tsx:1978](../app/workspace/Workbench.tsx:1978) 只有一次升冪陣列操作，圖示固定，沒有 sort mode／direction。建議有「手動、名稱升冪、名稱降冪」狀態；按鈕切換升降冪並切換 SVG／tooltip，更多選單回手動。名稱排序是每專案視圖偏好，不覆寫手排順序；同層資料夾與文件分別自然數字排序，新建／更名後維持目前模式。沒有可排序項目時停用；無需每次 toast。

同类缺陷：首次從磁碟載入沒有採用 metadata.files 的手排順序；拖到不同資料夾的檔案列只是排序、拖到資料夾標題才移動。需分別呈現插入線與移入高亮，避免做了操作卻看不到效果。建立文件服務在寫入失敗時會保留 error 文件，UI 不能只看回傳物件存在便報成功。

### R04：閱讀模式要有語義節奏

根因是逐行換造型，缺少「場景 → 段落 → 動作群 → 分支」的節奏資料。[reading.css:146](../app/reading/reading.css:146) 正文 29px，命令／if 卻是 14×1.65＝23.1px；場景尾把留白放在线前，線後空白又壓成 0；if／else 只有上 padding，分支尾不對稱。

水平問題也要精確處理：所有 `.cm-line` 現在同為左右 12px，不是每行 CSS 左距都錯。if 有 SVG＋6px、台詞直接從角色開始、set 無前導 icon，造成不同文字起點。應定義區域邊緣、固定圖示欄、文字欄，長行換行也跟同一文字基準。

| 視覺關係 | 建議初始值／規則 |
|---|---|
| 正文 | 保留 16px，預設行高試 30–32px；尊重已有閱讀偏好 |
| 命令與條件 | 可用 14–15px 次要字級，行框由閱讀行高推導，不再独立縮成 23px |
| 同一段台詞 | 靠行高保持連續，不每行加一段 margin |
| 台詞與命令群 | 群組交界 8–12px；連續命令內不重複加群組距離 |
| 標題／tags／正文 | 標題至 tags 約 6px，tags 至正文 20–24px |
| 場景分隔 | 線前、線後各約 24px；不可下一標題貼線、上一場景遠離線 |
| 條件區域 | 左右 16px，每個分支上下各 12–16px，標頭至內容 8px；if／elseif／else／結尾採同一配方 |
| 選項群 | 群組前後 16px、兄弟選項 12–16px；目的地緊跟自己的選項，選項後共同內容有明確結束 |
| 圖示基準 | 16px SVG＋8px 間隔，條件／命令／選項共用，避免自然字寬決定位置 |

正文亮度優先，角色以適量字重辨識；命令次要、參數中性灰、變數紫標籤、tags 低權重。內嵌選項條件應呈現低權重條件提示，不能只把變數變紫仍留下整段 `<<if>>`。深層保持平面閱讀起點，但內層結束與返回上層要有提示，不能看成全部條件已結束。

實作需增加僅供顯示的段落／命令群／分支首尾分類，保留一個 CodeMirror、原文 offset 與連續選取；不靠來源空白行湊版面、不改寫原文。語法揭露不應使周邊行框劇烈跳動。現有功能測試沒有驗證線前／線後與分支首尾的視覺幾何，需補真實 editor 的尺寸與長行／大字級截圖驗收。

### R05：流程圖提供真正的節點內編輯

根因：[Graph.tsx:104](../app/Graph.tsx:104) 只有導航回呼，Enter、雙擊與鉛筆都呼叫 open，再交由 Workbench 切去原文。加更多跳轉按鈕不能滿足節點直接改稿。

建議平時維持摘要，單擊選取；雙擊內容、Enter 或鉛筆讓**該節點原位展開**為約 420–520px 寬的連續閱讀編輯面，一次一顆，其他節點保留上下文。能直接改台詞、角色、命令／參數、變數與未知原文；角色更動僅作用該行，不能默默全專案替換。場景名稱確認後使用既有安全更名／引用更新交易。明確「前往原文」保留為次要動作。

- 內容區的選取、滾輪和輸入不觸發拖節點／縮放；標題把手供拖動。文字焦點的 Undo 改稿，畫布焦點的 Undo 改布局。
- 低縮放进入編輯時一次調整到可讀比例，按鍵輸入不持續追著游標縮放；其他節點位置固定，不隨打字自動整理全圖。
- Esc／收合退出編輯，已提交內容保留；先讓 IME／補全消耗 Esc，不銷毀正在組字的 editor。
- 共用來源交易、保存及閱讀裝飾；不能將摘要或 DOM 回生成全文。跨檔實體節點可改其 DocumentId，顯示檔案身份，不改活動 tab；動態／缺失目標不可假造可編輯內容。
- parser 現有 node ID 包含檔名／場景名／重複序號，改名或暫時非法語法會使其改變。必須以穩定文件身份及映射來源錨點保住編輯會話；外部修改破壞範圍時停止錯位套用，保留輸入並提示。

這是本次最大的功能增量，應獨立驗收來源／CRLF／BOM、跨窗 Undo、暫時非法內容、IME、跨檔及視野穩定。圖上拉線改寫劇本、多節點同時編輯等仍另列後續，不與基本節點直編混在一起。

### R06：大綱只保留一個顯示開關

目前有固定偏好、臨時顯示及關閉三種行為，卻沒有清楚說明其差異。建議移除面板內 pin 與 close，只留文件工具列的 toggle，並記住每模式的開關；大綱標頭只保留標題、數量和新增場景。普通換稿／搜尋定位不自動改大綱顯示。窄窗臨時避讓不覆寫偏好；toggle 的視覺狀態必須反映實際可見狀態。隱藏大綱保留其查詢、選取與捲動，重開回到原上下文。

已從程式碼確認的鄰近缺陷：未固定大綱點場景會走 `resetTransient()`，可能自行關掉；窄窗由 CSS 隱藏大綱，toggle 卻仍使用未考慮避讓的狀態，出現亮著卻不可見。移除 temporary 狀態後，普通導航與 Esc 不清除大綱偏好；歷史暫代右側時只暫時遮蔽，關閉歷史恢復大綱。窄窗點被遮住的大綱 toggle 應先顯示，不能第一下就關閉隱藏中的偏好。搜尋改浮層也需移除其自動開左欄／改 sideFocus 的副作用。

### R07：結構檢查與面板層次一起整理

[Workbench.tsx:2338](../app/workspace/Workbench.tsx:2338) 仍使用兩個原生 select；[workspace.css:82](../app/workspace/workspace.css:82) 只給少量 padding／字級修補。標題使用 flex 撐開，但缺少完整工具群組與 gap；右側大綱固定 260px，底部檢查固定 210px，只有左欄有 resize 手把。

- 檢查標頭採「標題＋數量／工具群／關閉」；等高約 30px、工具間 8px、左右 12–16px。將『非官方編譯器』移入資訊提示，避免常駐搶占標題。
- 少量互斥範圍適合分段「目前劇本／全專案」，嚴重度可用「全部／錯誤／提醒」分段並附數量；窄窗才降為有統一皮膚的 select。文字不可為省空間全部換成難辨 icon。
- 展開式選單需統一 trigger 高度、文字與 SVG 箭頭基線、選單起點、selected／focus；自訂指令的參數型別 select 也屬同類，不能只修檢查頁。
- 沒問題的空態不必占固定 210px；首次可縮成緊湊結果區，使用者主動拉高後則尊重尺寸。左右與下方面板都有一致 splitter 命中區、hover／focus、鍵盤調整与記憶尺寸。
- 整個 App 建立工作殼、停駐面板、主編輯面、浮層四級表面。用克制的底色差、約 6–8px 溝槽／局部 6–8px 圓角與 1px 描邊讓區域獨立；停駐面板不需要全部加大陰影。浮層才用明確柔影，自訂指令再加遮罩。

『劇本扁平呈現』不等於『整個視窗沒有層次』。主編輯面應有可辨識的承載範圍；大綱和檢查是輔助面，不能只是相近黑色背景上的幾條長分隔線。[Fluent 的 elevation](https://fluent2.microsoft.design/elevation) 使用陰影／邊緣表達表面關係，[material](https://fluent2.microsoft.design/material) 則區分一般表面與壓暗 modal 背景；本產品應採用這些層次原則，不需要堆疊模糊或裝飾卡片。

### R08：正文以外物件簡單低調

使用者於開始實作後明確補充：正文以外物件應簡單低調。採用低彩度角色、命令、tags、變數與接近正文底色的條件區域；不以更多亮色、強邊框、裝飾卡片或新增圖示辨認每一種語法。主次先由字級、群組間距及對齊建立，再以色彩輔助。操作 SVG 保留一致尺寸／語義與可及名稱，不能將必要操作回饋一起淡化。

閱讀層已實作並取得可重現的局部證據：18 項來源／裝飾／語義間距測試，以及 [CodeMirror 幾何與編輯 harness](../outputs/reading-refinement/harness/results.json)。實測命令和正文同行框、條件和正文文字 x 起點相同、分支內距 16／16px、場景線前後 24／24px，另驗跨區塊貼上／Undo／Redo、折疊與字級比例。這不能替代完整 App、打包版或原生輸入法驗收；本輪其他模組仍由主代理整合及總驗證。

## 具體改善方案：建議採用的配置

本節依使用者後續要求，將審查收斂成可執行的選擇。以下是第一輪曾批准並在 0.3.0 落地的歷史方向；後文保留修改前問題與證據。**與 R01–R08 衝突的規則已汰換，不再優先於本輪決策；現行值只見 UI 規範。**

### D01：左側專案、右側目前文件（大綱 pin 規則已由 R06 取代）

**選擇：檔案樹留左側，場景大綱移至可收合、可釘選的右側。** 左側回答「我要開哪一份稿」，右側回答「這份稿有哪些場景／目前在什麼位置」。不讓兩份列表搶同一個垂直空間，也不把兩者改成必須一直切換的互斥頁籤。

右側不必永遠占一整欄：初次開短稿可收起，工具列保留「大綱」入口；作者展開或釘選後記住偏好。大綱只呈現場景名與目前位置，搜尋按需展開，不逐列加 tags、行號或統計。縮小視窗暫時收起的欄位，不覆寫使用者的釘選偏好。

| 視窗寬度（CSSpx，設計起點） | 配置 |
|---|---|
| 1440 | 左220＋主區960＋右260；右側收起時空間全部交回主區 |
| 約1000–1279 | 一次保留一個輔助欄；手動開右側時暫時收起左側，關閉後恢復 |
| 800 | 主區優先；需要導航時開一個暫時抽屜，左右不一起覆蓋 |

專案搜尋使用左欄取代檔案樹；右欄在閱讀時是大綱，在歷史模式是版本列表。流程圖初次進入時右欄收起；明確開啟詳情後，選取節點才更新它，點節點不自動推擠畫布。各模式分別記住布局。

### D02：日常畫面只保留兩條水平列

第一列保留 Windows caption＋專案＋文件 tabs。第二列是精簡文件工具列：返回／前進、純文字／閱讀／流程切換、保存狀態、歷史、大綱與更多操作。當 tab 已能識別文件時，不再另寫一次同名大標題；完整路徑透過 breadcrumb 或提示按需要呈現。

**刪除第三條圖表文件標題列，以及為零散資訊保留的常駐 footer。** 圖表整理／視野工具在畫布角落共用一個緊湊控制組；檢查入口在有問題時顯示計數，詳細作者統計放進可展開面板。

布局規則：相關物件以8–12px間距聚成一組，不使用整頁 `space-between` 拉散每個欄位。工具列的彈性空間只用來分開「導航／視圖」與「文件動作」兩個真正不同的群組，不為每個小功能新增一整列。閱讀欄外側留白用於限制行長，應保留；空的工具列或重複標題不具相同價值。

### D03：節點改成資訊精簡、依內容決定高度的卡片

**預設只保留場景名＋最多兩行正文預覽。** 若沒有有效預覽，卡片自然縮短。以寬220–240px、內距12px為初始值，取消固定180px高度。長名稱最多兩行，完整名稱仍能查看。

| 目前資訊 | 下一版放置方式 |
|---|---|
| 每張卡的「場景」類型標示 | 一般場景直接刪除；只有特殊狀態才標示 |
| tags、來源行號、命令列表 | 預設移至選取詳情，不在每張卡常駐 |
| 原始 jump 小字＋框起來的分支文字 | 改成靠近來源的簡短分支理由；區分選項、若／否則、直接轉場，完整語義可展開 |
| 外部檔案的大型場景卡與強白邊 | 改成緊湊跨檔入口「↗ 場景名＋相對檔案位置」 |
| 缺失／無法解析的目標 | 保留明確警告，不以一般卡片假裝存在 |

線路固定主要閱讀方向，分離往返端點與路徑；標籤不拋到遠方再拉斜虛線。先修完整條件資料，再做線路外觀。正常縮放應能讀分支理由；遠景只保留場景與走向，選取關係時由固定詳情區顯示完整條件，不讓關鍵資訊縮成微小字。

### D04：設定使用完整專屬工作區（指令 tab／命名 modal 部分已汰換）

**選擇完整設定頁，不再把每一類偏好拆成一個小彈窗，也不把設定表單塞在劇本左右欄之間。** 開啟時保留頂部分頁，以下整區改成設定工作區：左側分類約180–200px，右側表單寬度上限640–720px，整組置於可用區域；不顯示劇本樹、大綱、文件模式開關或編輯統計。

分類初期只需「顯示與閱讀」「編輯與保存」「快捷鍵」「關於」。少量選项不必拆成更多分類。開啟時焦點放在設定標題或分類，不自動選取第一個數值欄位；返回編輯恢復原分頁、游標、選取、捲動及鍵盤焦點。

設定表單使用固定、就近的 label/value 網格：標籤約160–200px、欄間距24px，控制項依內容定寬。不能讓「字級」在最左而「16」在整個視窗最右。閱讀設定可即時預覽並自動保存偏好；輸入過程保留暫時字串，Enter／離開欄位才驗證，錯誤留在欄位旁。

自訂指令是專案工具，使用同樣的完整工作區，但左側直接是指令清單、右側是定義；頂部明示所屬專案。**不再出現「劇本樹＋設定分類＋指令清單＋表單」多層側欄。** 參數以緊湊列呈現名稱、類型、必填與預設值，複雜說明再展開。合法定義採明確「套用變更」，非法草稿另行保留，不照搬劇本的自動提交規則。

小型彈窗只保留給單步任務，例如重新命名、必要的破壞性確認。就地短暫調整可用小浮層，但不是每個偏好的唯一入口。

### D05：歷史入口放在文件工具列，版本預覽留在原文件上下文

Notion 官方目前說明：可以从頁面上方「⋯ → Version history」進入，也有頁面頂部時鐘入口；選擇版本能查看當時內容及變更重點，再還原版本。這支持文件層級的入口，但不代表需要複製其整套雲端／協作介面。[官方版本歷史說明](https://www.notion.com/help/duplicate-delete-and-restore-content)

Yarn Workbench 採下列固定流程：

1. 文件工具列提供時鐘「版本歷史」按鈕，與保存狀態鄰近；只開目前文件。
2. 右欄替換成此文件的版本時間線，按日期分組；顯示時間及必要版本原因。
3. 主區轉為清楚標示的歷史唯讀預覽，沿用目前閱讀位置附近的內容。預覽不建立編輯交易、不觸發保存。
4. 工具列改成「歷史版本／唯讀」＋「內容／差異」切換＋「返回目前稿件／還原此版本」。使用原有工具列空間，不再疊一條常駐列。
5. 只有按還原才修改文件；先保留目前版本，還原後可撤銷。若預覽期間其他視窗修改了文件，還原前更新比較並確認新的影響，不默默蓋掉新內容。
6. 返回目前稿件時恢復進入前模式、布局、游標／選取、捲動／圖表視野與焦點。

「快照」是自動版本的產生機制，使用者入口統一叫「版本歷史」，不再提供兩個意思重複的選單。「最近刪除」屬整個專案，保留獨立入口，列出檔案及內容預覽；不與每份文件的歷史混排。

### D06：搜尋分成快速開啟與持續查找（已由 R01 浮層規則取代）

**全文搜尋使用左側持續結果面板；Ctrl+P 使用輕量快速開啟浮層。** 浮層本身不是錯，適合一次找文件就結束；角色用法、台詞或變數的反覆比對需要可保留的結果。

全文搜尋進入後聚焦輸入，直接顯示結果，不用大型標題、說明段落或提交按鈕模擬表單。結果按文件／場景分組，顯示命中片段、高亮與結果數。點擊或 Enter 更新主編輯器，保留查詢、列表捲動與選取；返回檔案樹也不清掉上次查詢。上下鍵選結果，Ctrl+Enter 開新視圖；滑鼠與鍵盤遵守同一模式規則。

預設在目前模式定位；圖表只標示「場景包含命中內容」，不假裝精確文字命中已在圖上顯示，提供明確閱讀／原文定位入口。結果超過上限時顯示範圍或載入更多。空輸入顯示最近查詢；零結果提供簡短可理解狀態。

### D07：渲染版面先定四層（間距及低調呈現由 R04／R08 修訂）

閱讀順序固定為「場景 → 台詞 → 分支關係／命令 → metadata」。標題、正文、控制流和附屬資訊，必須先以尺寸、位置、間距分層，不能只靠顏色。

| 角色 | 提案起始值與布局 |
|---|---|
| 閱讀欄 | 標準最大約760px，寬版約900px；隨可用空間縮小，所有條件色面／分隔不超出此欄 |
| 場景標題 | 正文的約1.4倍；展開箭頭與標題同基線；下一場景間距32px |
| 場景 tags | 標題下6px，以灰色小標籤緊密成組；與正文間距16px；不逐項加圖示或隨機色 |
| 台詞 | 預設16px／28–29px；角色與台詞同行，連續台詞不額外加大片空白；自然段落間距12px |
| 命令 | 約正文0.875倍，行高約1.6倍；與所屬台詞接近，連續命令紧密排列；圖示與參數共用基線 |
| 變數 | 約正文0.9倍、紫色淡底，內距約1px 5px；保留完整識別字，字串與未知語法不可誤當變數 |
| 條件區域 | 淡底、左右12–16px、上下10–12px；若／否則共享區域邊界，同層只用一條分界；結束後回到普通正文 |
| 選項 | 選項與所屬內容緊接；兄弟選項間距約10–12px，僅組間需要細分隔；不把每個選項做成大條帶 |

以上數值是要實測的設計起點，不是從截圖推得的既有規格。字級設定需帶動整套相對比例，標題不能在正文放大後反而變小。

單純「選項＋一個 jump」可用緊邻的兩行呈現：選項為主、目的地為次，不把目的地放到閱讀欄最右。若未來評估同列表示，必須能維持連續選取、游標、貼上及撤銷；第一版不以來源操作不穩定換取少一行。

語法揭露是另外一個明確狀態：只揭露必要範圍；結構行正在編輯時有低權重提示，離開恢復分隔，避免 `===` 与裝飾線重複。折疊為緊湊場景列，收起後不保留展開區域的巨大外距。來源空白與註解仍完整保存，呈現壓縮不修改原稿。

### D08：共用物件布局與 padding 規則

| 物件 | 建議配方 |
|---|---|
| 一般工具列 | 高40–44px，左右12–16px；一組內6–8px，不同功能組12–16px |
| 側欄清單 | 列高32–36px，左右12px；完整列可選；尾端⋯及狀態保留固定空間，避免 hover 時文字跳動 |
| 面板 | 內距16px；標题與第一個控制項12px，區組之間24px |
| 表單 | 標籤／值鄰近排列，列間12–16px；長說明可換行，錯誤跟在所屬欄位 |
| 分段單選 | 外容器內距3px，選項高28–32px，水平內距10–12px；依文字決定總寬，不填滿整行 |
| 圖示 | 通常16px，互動命中區至少約32px；圖示、文字與數字基線對齊 |

空間規則統一使用少量4／8／12／16／24／32px階距，但依角色選擇，不為湊整數而重寫所有細節。只在真正區域邊界畫分隔，不給每個欄位與每行台詞一個框。selected、hover、focus 分開；維持可見焦點，不以刪 outline 達成「乾淨」。

### D09：互斥少量選項使用一組分段單選，不是一排獨立按鈕

**採用橫向分段單選的對象**：純文字／閱讀／流程；歷史的內容／差異；閱讀寬度的標準／寬版。這些都在切換同一個屬性，任何時候只有一個值生效。

使用共同低對比容器、清楚的選中底塊；整組只有一個值，支援方向鍵切換並保留焦點。功能不同的動作（歷史、搜尋、檢查、儲存）不能併進去；開／關用 switch，很多選項用 select，需要解釋不同選項時用 radio，複選 tags 不套單選造型。滑動底塊可有短過渡，但不是辨認選中狀態的唯一依據。

### D10：正常自動保存移除常駐 Save，保留明確的例外操作

| 文件狀態 | 工具列與動作 |
|---|---|
| 已成功寫回原檔 | 低權重「已儲存」，無常駐儲存按鈕 |
| 有等待保存的修改／保存中 | 等待或進行中狀態；成功後才回到「已儲存」，不彈成功 toast |
| 內容已保存於草稿區，尚無磁碟路徑 | 「本機草稿」＋可發現的「存成檔案…」；不使用危險感的未保存圓點 |
| 保存失敗 | 在文件範圍顯示原因與「重試」，保留內容 |
| 外部衝突 | 明確的「比較／處理衝突」入口，不能由背景自動保存覆蓋 |

Ctrl+S 保留立即寫入，Save All 留在選單／快捷鍵，另存與匯出仍可取得。移除的是日常常駐按鈕，不移除人工保存能力。指令定義的「套用變更」保留，因其具有驗證與影響其他文件的提交語義。

### 落地順序與方案邊界

先完成T01–T04正確性修正及保存狀態契約；接著實作D01／D02／D04／D05／D06的工作區切換和焦點恢復，再以D07／D08／D09統一渲染與控制項，最後處理D03圖表節點與路線。

## 主要判斷

目前功能完成度高於設計整合度：視窗、文件、閱讀、圖表、設定各自有功能，但資訊層級與互動契約不一致。畫面上最占空間的元素，往往不是作者最需要看的內容；有些功能提供了入口，卻沒有完成使用者真正的任務。

三個關鍵例子：

- 復原提供了快照列表，卻沒有協助作者判斷「哪一版才是我要的」。
- 流程圖畫出了 jump，卻可能遺失「為什麼可以走到這裡」的條件。
- 渲染把原文換成標籤與顏色，卻未統一閱讀欄、段落節奏、收合與語法編輯狀態。

因此改善應先處理語義、任務與狀態，再調整布局及元件外觀。增加更多顏色、卡片或圖示，無法解決上述問題。

## 證據與優先級

- **實測**：隔離 profile 的 0.2.1 打包 App，1440×900 CSSpx、scale factor 1；或直接執行目前 parser。是本輪實際重現。
- **源碼**：找到目前使用的事件、資料流或樣式；不等同所有互動狀態均經實測。
- **截圖**：使用者提供畫面可觀察的呈現。原圖 1–6 為 3200×1998，不能當成 CSS 尺寸；7–9 為裁切，不能憑圖大就說控制項字級過大。
- **提案／推論**：根據作者任務分析的改善方向，尚未透過作者測試證明效率提升。

P1：資訊可信度或實際輸入／導航錯誤。P2：核心閱讀與日常流程持續受阻。P3：低頻資訊與視覺整理。分項報告的原始評級不直接累加，以下為合併後排序。

## 指令管理（圖 5）

這頁適合一個有明確專案範圍的「指令清單＋定義」工作區。現在同時展開劇本清單、指令清單、寬表單，造成兩個導航中心。

- **任務布局**：保留指令 tab，但讓左側呈現此任務需要的清單，或為指令頁記住收合的劇本側欄；回到劇本時恢復作者原有布局。不要無預警永久關掉全域導航。
- **表單寬度**：短命令名不必橫跨大半視窗；建立合適表單寬度，欄位名稱、值、錯誤靠在一起。
- **參數表示**：一個參數不需要一張大型卡片。以名稱／類型／必填／預設值的緊湊列為主，複雜資訊再展開；保留欄位標籤、錯誤與非拖曳排序途徑。
- **提交狀態**：已保存時 Save 不該仍像待提交；保留明確的「套用變更」與草稿狀態。指令設定有最後有效版本和非法草稿，不宜因劇本 autosave 就一律自動提交。
- **動作分層**：現在 Save、複製、Undo、Redo、刪除排在一起。將「複製」改成意思準確的「建立副本」；低頻與刪除移至所屬項目選單；Undo／Redo依是否可用呈現狀態。多參數表單的主要提交動作不能只在最底部。

圖 7／9 的明亮焦點不是「沒設計就隨便畫的白框」：實测是 2px 淡藍 outline，加上 focus border，形成雙輪廓。可以統一為清楚的一套表現，**不能移除鍵盤焦點**。圖 6–9 的低灰對話框邊界可保留；更大的問題是所有任务都借用同一個中央 modal。

## 建議執行次序與驗收

1. **可信度與實際操作**：T01–T04、設定重設範圍、搜尋結果上限。驗收要確認資料和所有入口表達相同的事。
2. **閱讀編輯器整體設計**：一起處理閱讀欄、段落節奏、字級比例、收合、語法揭露、條件與選項，避免逐個框修完後再次互相衝突。
3. **流程圖語義與可讀性**：在完整來源條件上設計分支標籤，再處理往返路徑、外部入口、縮放和節點內容。
4. **輔助任務形式**：搜尋結果面板、復原預覽、指令管理與偏好設定；最後減少重複 toolbar、footer 及說明文案。

驗收不只檢查按鈕有無反應：

- 同一份稿的閱讀／圖表都能辨認所有分支條件與共同後續；未知語法不能被假造為已理解。
- 正常保存、草稿、保存中、衝突、失敗，各處對同一文件說法一致。
- 一次輸入數字、鍵盤選搜尋第二筆、恢復指定舊版本，都能自然完成。
- 渲染進出語法／折疊／跨場景選取不丟游標與來源；未修改部分的註解、空白、BOM、CRLF 不變。
- 800／1440 CSSpx、閱讀尺寸最小／最大、短／長台詞與長名稱、多文件和多分支，均不依靠固定截圖座標才能成立。
- 灰 tags、紫變數、角色與台詞同行、單一連續編輯面、純文字既有樣式、Windows caption、鍵盤 focus 與恢復保障，皆保留。
