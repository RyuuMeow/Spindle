## 證據與排序方式

- 「已具備／部分／缺少」依目前實作確認。源碼可確認事件、資料流與入口是否存在，不等同本輪實際操作過全部路徑。
- 上一輪 `打包版結果` (local verification artifact) 已驗證文字右鍵、撤銷重做、保存重載、分頁溢位與圖表操作。本輪沒有重跑完整 UI／build；僅新增三個記憶體內 parser 檢查。
- 損毀恢復問題引用 `先前隔離測試` (local verification artifact) 並核對目前程式仍有同一資料流；不是宣稱本輪重新實測。
- 優先級是設計／工程判斷，並非量測過的使用頻率：**P0** 可能損失內容；**P1** 高頻基本工作或其必要保護；**P2** 效率與連續性；**P3** 另立範圍的產品延伸。

### 語義呈現與寫作體驗

此範圍依使用者提出的 Typora 原文／渲染、分隔線與分區方向補充。**結構化呈現列為 P1 核心編輯體驗，不以完成執行引擎或多視窗為前提。** 使用者後續明確要求「純文字模式應該跟原本一樣」，並否決初稿過多標籤、箭頭與框線的複雜呈現。現行方向是純文字沿用現有編輯器；只有渲染模式採輕量排版。簡化示意尚未接入產品，也不是完整即時編輯器。

使用者另補充渲染可利用顏色與造型：變數可隱藏 `$` 並採淡色標籤，命令／條件可用圖示與短文字，區塊改用平面區域，不依賴多層縮排。具體配色、造型與語義邊界集中記於 [UI 規範](../ui-design.md)，純文字模式不變；「簡化」不等於只能保留原始語法文字。

目前 [CodeEditor:23](../../app/CodeEditor.tsx#L23) 已辨識標頭、分隔符、選項與指令 token；純文字維持既有上色、字級、行距、縮排、行號偏好與編輯操作。現有 [場景資料](../../app/parser.ts#L6) 有 start/body/end，可用於渲染場景邊界。現有 folding 關閉並不授權本次更動純文字模式。

|---|---|---|---|
| E01 | 渲染模式的場景層級 | 只在渲染模式將 `title:` 呈現為標題，以留白／細線區分場景；避免重複「場景結束」標籤與標頭底板。 | P1；純文字不新增裝飾、底色或額外分隔線。 |

| E09 | 標籤、註解與 markup | 場景 tags 在標題下呈現為獨立的中性灰色小標籤，可換行且與紫色變數區分；行 tags、行 ID、註解有較低視覺權重與展開入口；已支援 markup 可呈現其範圍，未知語法顯示原文。 | P2；不能把任意 markup 名稱推成顏色／動畫，也不能讓收合內容無法發現。 |

| E11 | 閱讀、原文與圖表共同定位 | 模式切換保留閱讀錨點；需要精確編輯時可透過區塊操作／右鍵回原文，正常閱讀不顯示逐行行號與跳轉箭頭。 | P1，E02 的必要條件；來源範圍是內部能力，不必以大量操作按鈕常駐呈現。 |
| E12 | 作者統計與輕量篩選 | 選取／場景／全稿的台詞量、選項數、角色台詞量；角色、tag 與註解可作查找入口；閱讀字級、行寬與行距可調。 | P2；中文字符／英文詞數口徑清楚。分支總字數不等於單次遊玩量，不以估計冒充遊玩時間。 |

實作分層：

1. **保留純文字**：繼續使用既有 Monaco model 與目前外觀、輸入法、快捷鍵及撤銷行為。本次不加入原文 decorations、場景底色、摺疊或文字重新排版。
2. **簡化渲染閱讀**：補保留原始範圍的對話／選項／條件閱讀結構，用必要標題、淡色標籤、圖示、平面區域與分隔降低語法雜訊；不以遞增縮排為主要分組手段。現有 `summary/calls/links` 不足以重建完整劇本；未知與解析失敗片段須回退原文。閱讀層由 `Doc.text` 衍生，不另存第二份內容，不由閱讀 DOM 反向重寫整份文字。
3. **即時排版編輯**：先做區塊原文編輯，再處理跨區塊游標、選取、貼上與共同 undo。中文 IME 組字中不重新掛載輸入區；完成這些之後才稱為即時編輯，而不是把 readonly preview 換名。

共同驗收：原文／閱讀往返不改任何原始字元；保留註解、空白、CRLF、未知語法；重複台詞能定位正確來源；搜尋及錯誤可展開對應區塊；未閉合指令不吞掉後續內容；中文組字、跨行貼上與撤銷重做完整。只切換呈現不產生 dirty 或新增 undo 紀錄。

閱讀渲染與執行試讀分開：閱讀呈現所有條件與分支，保留原始表達式；執行試讀才需要變數值、條件求值、once 狀態及外部指令處理。Yarn 的 `---`／`===` 具有場景結構語義，不能直接套用 Markdown renderer。[Yarn 節點與台詞](https://docs.yarnspinner.dev/write-yarn-scripts/scripting-fundamentals/lines-nodes-and-options)

## 排序與右鍵不應一律套同一種行為

| 操作對象 | 排序實際改變什麼 | 右鍵的最小合理動作 |
|---|---|---|
| 分頁 | 個人工作視圖順序，不改文字或檔案 | 關閉、關閉其他／右側、重開已關閉、同稿新視圖、移至新視窗；固定稍後補。 |
| 文件列表 | 顯示順序；拖入資料夾才是磁碟移動 | 在新分頁開啟、更名、複製、下載／另存、移除；有原檔後提供顯示位置與複製路徑。 |
| 場景列表 | 若按原文排序，拖動會改寫整段原文；不代表 jump 邏輯改變 | 前往原文、同稿新視圖、更名及更新引用、複製、移動、刪除、查看引用。 |
| 指令參數 | 位置參數契約；會影響既有呼叫的解讀 | 保留現有上／下移，提供影響說明。拖動只是替代入口，優先級低於其他缺口。 |
| 圖表節點 | 只改視覺位置；目前已支援 | 編輯原文、在新視圖開啟、查看引用、複製場景名。缺失目標可提供建立目標；動態目標不假裝可建立。 |
| 圖表空白 | 畫布視野與新增位置 | 建立場景、適應全部、回到 100%、自動整理／復原布局。 |

右鍵不得只作用在「原本選取」而忽略滑鼠下的物件。關閉／刪除前應顯示正確目標；選單關閉要恢復焦點。既有「⋯」入口保留，讓沒有右鍵的使用者也能完成操作。

## 兩個新確認的建立流程缺陷

1. **名稱規則不一致。** 新增場景使用 `/^[A-Za-z_][A-Za-z0-9_]*$/`，允許 `_Start`；parser 使用英文字母開頭規則，建立後立即報錯。[建立處](../../app/page.tsx#L60)、[解析處](../../app/parser.ts#L18)。最小驗收：建立與檢查共用同一名稱規則，合法／非法案例一致。
2. **預設場景名可能碰撞。** 新增劇本用 `NewNode + (節點數 + 1)`；當唯一場景叫 `NewNode2`，新劇本也建立 `NewNode2`，兩者都報重名。[page:95](../../app/page.tsx#L95)。最小驗收：用專案唯一命名流程尋找下一個可用名稱，包含非連續數字命名案例。

本輪以 Node 載入並轉譯 `app/parser.ts` 後在記憶體中確認以上兩例。另測 `title: Start\n---\n<<if ( >>\n<<endif>>\n===` 得到空 issues，確認目前沒有完整 expression 檢查；這與已記載的 parser 範圍相符，不列成官方編譯器錯誤。

## 實作依賴與分批建議

**第一批：內容保護、操作基本盤與簡化渲染設計。** 修 R01 及兩個建立缺陷；補指令草稿恢復、刪除／匯入前快照、Save All。分頁拖移、右鍵、快捷鍵、重開關閉分頁可平行完成。呈現方向保留純文字原樣，另做簡化渲染模式；不將裝飾或折疊自動加入純文字。

**第二批：真正使用磁碟專案。** 建立專案／文件身分及受限檔案服務，完成開啟資料夾 → 編輯 → 原檔保存 → 關閉 → 最近專案再開的完整流程。同時處理相對路徑、同名文件、外部修改與失敗保護。再把更名、路徑動作、OS 拖入／開啟接上同一組動作。

**第三批：查找與連續工作。** 全專案搜尋、快速開啟、返回歷史、場景引用與安全更名、完整 session／視窗位置、圖表拖移 Undo/Redo。跨檔取代只在具備預覽與整批復原後提供。

**第四批：多視窗。** 先完成共享文件狀態及跨視窗編輯協調，提供選單「移至新視窗」，再做拖出／拖回。多視窗不必等所有資料夾功能完成；它真正依賴的是穩定文件身分、共享狀態及保存／關閉契約。

**作者呈現可以獨立推進。** 純文字模式維持現況；渲染模式沿「保留來源範圍 → 簡化閱讀 → 區塊編輯 → 即時排版」發展，不必排在多視窗之後。真正執行試讀仍維持獨立範圍。

多視窗的必要驗收：

- A 視窗修改，B 視窗看到相同內容與 dirty 狀態；一邊保存不讓另一邊用過期內容覆蓋回來。
- 同文件不同視窗的游標、模式與視野獨立；撤銷重做不套用錯誤版本或弄丟另一邊修改。
- 拖出再拖回保留文字、視圖與選取，拖曳取消不遺失 tab；失敗時原視窗仍保有工作。
- 關閉其中一個視圖不等於刪文件；最後一個相關視窗的保存／取消處理正確。
- 重啟可恢復視窗與工作位置；拔除第二螢幕後視窗仍在可見範圍。

原生保存的必要驗收：取消選擇不改目前專案；不同資料夾同名檔不混淆；寫入成功才清 dirty；唯讀／寫入失敗保留草稿；偵測外部修改；備份失敗不繼續破壞性取代；舊工作區可遷移且保有救援副本。

## 值得做，但不當成本輪基本缺件

- **左右對照原文與圖表**：對作者有用，但應做一個簡單雙欄選項，不擴成任意停靠的 IDE。多視窗可先滿足雙螢幕情境。
- **故事試讀／選項預覽**：目前沒有 runtime；是有價值的作者產品能力，需先界定條件、變數、外部指令的執行語義。
- **全專案總圖、視覺拉線改寫 Yarn、完整編譯器、Unity 執行連接**：均涉及明確的新產品範圍，不能和「節點已能拖動」混為一談。
- 雲端同步、多人協作、外掛市集、終端機、Git 面板、分頁群組不列為基本桌面門檻。

## 比較依據

以相近任務取長處，不以功能數量追平競品；沒有使用 VS Code 作基準，也沒有冒稱本輪親自操作競品。

- [Notion Desktop](https://www.notion.com/help/notion-for-desktop)：新分頁可先開搜尋，連接找內容、建立內容及跳到已開分頁；支持 T05 的輕量入口提案。
- [Obsidian Tabs](https://obsidian.md/help/tabs)、[Pop-out windows](https://obsidian.md/help/pop-out-windows)：拖動排序、拖出視窗、固定、重開關閉分頁與跨窗移動是成熟的文件視圖操作。採用其操作可預期性，不照搬全部分組／布局系統。
- [Typora File Management](https://support.typora.io/File-Management/)：文件型 App 的資料夾、檔案右鍵、自然排序、外部變動、路徑揭示、快速開啟與全域搜尋，最貼近本工具需要補齊的磁碟工作流。
- [Typora 即時呈現](https://typora.io/)、[Markdown Reference](https://support.typora.io/Markdown-Reference/)：語法可呈現為內容結構，游標進入部分行內元素時重新顯示來源；作為原文／渲染及即時編輯的互動參照。Yarn 的顯示與邏輯語義須另外設計。
